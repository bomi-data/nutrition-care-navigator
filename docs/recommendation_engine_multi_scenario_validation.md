## 2. 시나리오 5개 — 결과

### A. 75세, 식사지원 필요가 매우 명확 (강원특별자치도 속초시)

- 입력: 장애 아니오·저소득 예·독거 예·거동불편 예·식사준비어려움 예·최근퇴원 아니오, `meal_support`
- 하드필터 funnel: 85 → 지역제외 81 → 연령제외 0 → 장애제외 0 → 저소득제외 0 → **최종 4건**
- 등급 분포: `HIGH_MATCH` 2 / `NEEDS_CONFIRMATION` 2

| 순위 | 서비스 | 유형 | 점수 | 등급 |
|---|---|---|---:|---|
| 1 | 저소득 재가노인 식사배달(지방이양) (속초시) | meal_support | 82.3 | HIGH_MATCH |
| 2 | 경로식당 무료급식소 운영 (속초시) | meal_support | 70.6 | HIGH_MATCH |
| 3 | 국가유공자재가복지지원 (전국) | home_visit | 17.6 | NEEDS_CONFIRMATION |
| 4 | 재가급여 (전국) | home_visit | 17.6 | NEEDS_CONFIRMATION |

**판정**: 정상. 원하는 도움(meal_support)과 직접 일치하는 지역 서비스 2건이 1·2위를 차지했고,
관련 없는 전국 서비스는 `NEEDS_CONFIRMATION`으로 명확히 구분되었습니다.

### B. 70세, 취약조건이 거의 없는 고령자 (전북특별자치도 군산시)

- 입력: 장애·저소득·독거·거동불편·식사준비어려움 전부 아니오, `meal_support`
- 하드필터 funnel: 85 → 지역제외 81 → 연령제외 0 → 장애제외 0 → **저소득제외 2** → 최종 2건
- 등급 분포: `NEEDS_CONFIRMATION` 2 (전부)

| 순위 | 서비스 | 유형 | 점수 | 등급 |
|---|---|---|---:|---|
| 1 | 국가유공자재가복지지원 (전국) | home_visit | 0.0 | NEEDS_CONFIRMATION |
| 2 | 재가급여 (전국) | home_visit | 0.0 | NEEDS_CONFIRMATION |

**판정**: 정상이지만 데이터 특성이 드러남. 군산시의 meal_support 서비스 2건(WLF00002076,
WLF00002352)은 모두 `low_income_required=true`인데 사용자가 명확히 "저소득 아님"이라고
답해 하드필터로 제외되었습니다. **이것은 필터 결함이 아니라, 실제 공공 식사지원 사업 대부분이
소득 기준으로 대상을 제한하는 정책 설계를 정확히 반영한 결과**입니다. 남은 2건은 관련 없는
유형(home_visit)이지만 점수 0.0으로 정직하게 최하위 등급 처리되어, 억지로 "확인해볼 만한
서비스"처럼 보이게 하지 않았습니다.

### C. 72세, 장애+저소득+거동불편 (서울특별시 성동구)

- 입력: 장애 예·저소득 예·독거 모름·거동불편 예·식사준비어려움 예, `meal_support`
- 하드필터 funnel: 85 → 지역제외 81 → 연령제외 0 → 장애제외 0 → 저소득제외 0 → 최종 4건
- 등급 분포: `HIGH_MATCH` 2 / `NEEDS_CONFIRMATION` 2

| 순위 | 서비스 | 유형 | 점수 | 등급 |
|---|---|---|---:|---|
| 1 | 중증 재가 장애인 밑반찬 지원 (성동구) | meal_support | 82.3 | HIGH_MATCH |
| 2 | 장애인무료급식소 운영 (성동구) | meal_support | 76.5 | HIGH_MATCH |
| 3 | 국가유공자재가복지지원 (전국) | home_visit | 17.6 | NEEDS_CONFIRMATION |

**판정**: 정상. 장애/저소득 조건이 정확히 반영되어 성동구의 장애인 대상 급식 서비스 2건이
그대로 1·2위. `lives_alone=모름`이 있어도 하드필터에는 영향 없이(§UNKNOWN 규칙) 정상 통과.

### D. 78세, 정보가 매우 부족 (충청북도, 시/군/구 모름, desired=모름)

- 입력: 장애·저소득·독거·거동불편·식사준비어려움 전부 모름, `desired_support=unsure`
- 하드필터 funnel: 85 → 지역제외 79 → 연령제외 0 → 장애제외 0 → 저소득제외 0 → 최종 6건
- 등급 분포: `NEEDS_CONFIRMATION` 6 (전부)

| 순위 | 서비스 | 유형 | 점수 | 등급 |

**판정**: 정상. `desired_support`가 `unsure`라 서비스유형 점수 요소가 아예 비활성화되고,
지역도 시/군/구를 몰라 정밀 확인이 안 되므로 전 후보가 `NEEDS_CONFIRMATION`으로 나왔습니다.
정보가 부족한 사용자에게 의도한 그대로의 동작입니다.

- 입력: 저소득 예·독거 예·거동불편 예·최근퇴원 예, `desired_support=[discharge_support, community_care]`
- 하드필터 funnel: 85 → 지역제외 81 → 연령제외 0 → 장애제외 0 → 저소득제외 0 → 최종 4건
- 등급 분포: `HIGH_MATCH` 1 / `NEEDS_CONFIRMATION` 3

| 1 | 함양군 통합돌봄사업 | community_care+discharge_support+home_visit+meal_support | 88.9 | HIGH_MATCH |

**판정**: 정상. 85건 중 `discharge_support` 태그를 가진 유일한 서비스(함양군 통합돌봄사업)가
정확히 지역·연령·조건 일치로 1위를 차지했습니다. meal_support 태그를 가진 4위 서비스는

정확히 강등되었습니다 — **meal_support 편중이 이 시나리오의 결과를 왜곡하지 않았습니다.**

## 4. 반복적으로 발견된 문제 vs 데이터 커버리지 문제

### 4.1 반복적으로 관찰되었지만 "이미 알려진, 이번엔 새로 발견되지 않은" 현상

- **NATIONAL 서비스가 tie-break로 1위가 되는 현상** (시나리오 B, D): 실제 신호가 있는
  시나리오(A/C/E)에서는 한 번도 발생하지 않았고, 정보가 극히 부족하거나(D) 실질적으로
  살아남은 후보가 전국 서비스뿐인 경우(B)에만 발생했습니다. `docs/recommendation_engine_
  v1_report.md` §9/§11에 이미 기록된 것과 **동일한 원인(동점 처리 시 service_id 오름차순
  fallback)**이며, 점수 자체가 실제로 더 높아서가 아니라는 점도 동일하게 재확인되었습니다.
  **새로운 문제가 아니라 기존에 알려진 문제의 재현입니다.**

### 4.2 데이터 커버리지 문제(엔진 결함 아님)

- **시나리오 B**: 비취약계층 고령자에게는 군산시의 meal_support 서비스가 저소득 요건으로
  하드 배제되어, 살아남는 후보가 사실상 전국 서비스 2건뿐이었습니다. 이는 **실제 공공
  식사지원 정책 대부분이 소득 기준으로 대상을 제한하기 때문**이며, 85건 데이터가 이를
  정확히 반영하고 있는 것입니다. 데이터를 더 모으더라도 "비취약계층 대상 무료 식사지원"
  자체가 현실에 흔치 않을 수 있어, 이 결과는 상당 부분 구조적으로 불가피합니다.
- **화성시(이전 검증)와 마찬가지로**, 특정 시/군/구에 서비스가 아예 없는 경우가 존재합니다
  (85건이 아직 전국을 다 커버하지 못함).

### 4.3 이번에 새로 발견된 엔진 구조적 문제

**없음.** 5개 시나리오와 화성시 회귀 사례 전체에서, 지난 턴에 수정한 로직(교집합 없는
서비스의 등급 강등)이 일관되게 정확히 작동했고, 그 외 새로운 이상 패턴은 발견되지 않았습니다.

## 6. 수정 필요 여부

**A. 현재 엔진으로 충분히 안정적 → 수정 없음.**

지난 턴에 수정한 `_determine_match_level`의 교집합 규칙이 이번 5개 시나리오 전체에서
일관되게 정확히 작동했습니다. 관찰된 두 가지 현상(§4.1 NATIONAL tie-break, §4.2 저소득
요건으로 인한 좁은 후보 풀)은 각각 **이미 알려진 UX 이슈**와 **데이터/정책 반영의 자연스러운
결과**이며, 코드 결함이 아닙니다. "결과가 마음에 들지 않는다"는 이유로 가중치나 필터를
조정하지 않았습니다.

## 7. RAG 단계 진입 가능 여부

**예, 가능합니다.** 엔진의 핵심 로직(하드필터/소프트스코어/등급판정/UNKNOWN 처리)이 서로
다른 5개 조건 + 1개 실사용 회귀 사례에서 일관되게 검증되었고, 새로운 차단 요소가 발견되지
않았습니다. RAG는 `docs/recommendation_system_design.md` §10 경계(원문 근거 검색 + 문장
재서술만, 판정 관여 금지)를 유지하는 조건으로 진행 가능합니다.
